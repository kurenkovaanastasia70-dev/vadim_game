Покрытие тестами

Теория, виды тестов и CI/CD на примере игры Vadim Game

Зачем нужны тесты

Автотест — программа, которая проверяет ожидаемое поведение игры. Тесты ловят регрессии после изменений, помогают безопасно работать в ветках и превращают требования к игре в исполняемую документацию.

Быстреене нужно каждый раз вручную проходить одинаковый сценарий
Надёжнееошибка обнаруживается сразу после push
Понятнеетест показывает, какое поведение считается правильным

Что такое покрытие

Покрытие показывает, какая часть кода выполнялась во время тестов. Базовая формула:

покрытие = выполненные инструкции / все инструкции × 100%

Покрытие строк не доказывает отсутствие ошибок: строка могла выполниться без проверки результата. Поэтому мы смотрим на процент вместе с качеством assertions и сценариев.

Виды покрытия

Строккакие исполняемые строки были запущены
Ветвейбыли ли проверены оба исхода условий if/else
Функцийкакие функции были вызваны тестами
Инструкцийосновная метрика coverage.py для исполняемых операторов

Как измерить покрытие

python -m coverage run -m unittest discover -s tests -v
python -m coverage report -m
python -m coverage html -d coverage_html

Таблица появляется в консоли, подробный отчёт — в coverage_html/index.html. В проекте тесты измеряют игровые модули, но не сами тесты, учебные скрипты и редактор уровней.

→

→
compile
→

Все jobs относятся к стадии test. Если одна проверка падает, pipeline красный. Deploy в проекте не настроен.

Главное правило

Не нужно гнаться только за процентом. Хороший тест проверяет наблюдаемое поведение: изменилось ли количество предметов, состояние игрока, уровень или экран. Лучше содержательное покрытие критических игровых сценариев, чем высокий процент пустыми проверками.
