# Занятие: фотоаппарат в стиле Phasmophobia

Цель занятия — добавить постоянно доступный фотоаппарат и пройти полный путь игровой механики: событие клавиатуры → геометрия кадра → поиск цели → оценка фотографии → награда → сохранение → тесты.

`draws.py` на занятии не пишем и построчно не разбираем. Его заранее готовит преподаватель, чтобы не тратить время на отрисовку. Разбираем весь смысловой код: `photo_camera.py`, `handlers.py`, `main_work.py` и `tests/test_photo_camera.py`.

## Правила механики до написания кода

- Фотоаппарат есть всегда и не занимает слот инвентаря.
- Клавиша съёмки — `C`.
- Камера фотографирует квадрат непосредственно перед игроком.
- Снимок можно делать не чаще одного раза в секунду.
- В журнал попадают только фотографии с видимым призраком.
- В журнале максимум пять зачётных фотографий.
- Качество фотографии получает редкость `1`, `2` или `3` звезды.
- Первая фотография призрака — `UNIQUE`, следующие — `DUPLICATE`.
- Базовая награда: `15$` за `UNIQUE`, `3$` за `DUPLICATE`.
- Итоговая награда равна базовой награде, умноженной на сложность `x1..x4`.
- Деньги начисляются сразу после удачного снимка.
- За промах и снимок сверх лимита деньги не начисляются.

Важно: звёзды показывают качество кадра. В текущей версии они не меняют денежную награду. Деньги определяют тип `UNIQUE/DUPLICATE` и коэффициент сложности.

## Шаг 3. Описать результат через `PhotoCapture`

```python
@dataclass(frozen=True)
class PhotoCapture:
    zone: pygame.Rect
    captured: bool = False
    rarity: int = 0
    subject: str = ""
    score: float = 0.0
```

- [ ] `dataclass` сам создаёт конструктор объекта.
- [ ] `frozen=True` запрещает случайно менять готовый результат.
- [ ] `zone` — квадрат мира, попавший в кадр.
- [ ] `captured` — найдена ли подходящая цель.
- [ ] `rarity` — 0 для промаха или 1–3 для удачного фото.
- [ ] `subject` — тип цели, сейчас `ghost`.
- [ ] `score` — внутренняя оценка качества от 0 до 1.

Отдельный объект надёжнее пяти возвращаемых значений, порядок которых легко перепутать.

## Шаг 6. Посчитать качество кадра

`_subject_score(...)` объединяет два критерия:

```python
score = 0.65 * distance_quality + 0.35 * center_quality
```

- [ ] Посчитать расстояние от игрока до цели через `math.hypot`.
- [ ] Превратить его в `distance_quality`: ближе — лучше.
- [ ] Посчитать боковое отклонение от центральной линии кадра.
- [ ] Превратить его в `center_quality`: ближе к центру — лучше.
- [ ] Дать расстоянию вес 65%, центрированию — 35%.

Обе оценки ограничены диапазоном от 0 до 1, значит итоговый `score` тоже остаётся в нём.

```python
if score >= 0.67:
    return 3
if score >= 0.38:
    return 2
return 1
```

- [ ] Объяснить порядок условий от высокого качества к низкому.
- [ ] Проверить граничные значения `0.67` и `0.38`.

## Шаг 7. Сделать снимок чистой функцией

`capture_ghost_photo(...)`:

- [ ] строит зону через `photo_zone`;
- [ ] перебирает призраков;
- [ ] пропускает невидимых и не пересекающихся с зоной;

```python

```

`lambda row: row[0]` говорит функции `max` сравнивать пары по оценке. Это важно, если в кадр одновременно попали несколько целей.

Функцию легко тестировать: ей не нужны экран, меню, сохранение или игровой цикл — только прямоугольник игрока и список целей.

## Шаг 13. Разобрать коэффициент и отчёт

`photo_reward_multiplier()` переводит индекс сложности `0..3` в множитель `1..4`:

```python
return max(1, min(4, int(self.difficulty_index) + 1))
```

`min` не даёт получить больше 4, `max` — меньше 1.

`get_photo_reward_breakdown()` не начисляет деньги. Он формирует отчёт: базовую сумму, коэффициент, число уникальных и повторных фото, общую уже заработанную сумму.

В `get_level_complete_reward_breakdown()` фото остаются в отчёте, но не прибавляются к `total` второй раз. Иначе одна фотография оплачивалась бы при съёмке и повторно при победе.

- [ ] Найти комментарий о немедленной оплате.
- [ ] Проверить `total = base + difficulty_bonus + evidence_bonus`.
- [ ] Объяснить разницу между «показать в отчёте» и «начислить».

## Шаг 15. Контракт готового `draws.py`

Этот файл пишет преподаватель. На занятии его не разбираем и не переписываем.

Достаточно знать, какие данные он читает:

- `game.photo_album` — количество зачётных фото;
- `game.get_photo_reward_breakdown()` — заработанная сумма;
- `game.camera_flash_until` — показывать ли вспышку;
- `game.camera_zone_until` и `game.last_photo.zone` — показывать ли квадрат;
- `game.camera_cooldown_until` — готова ли камера.

Интерфейс показывает понятную строку:

```text
КАМЕРА [C] | Фото: 2/5 | Заработано: 36$
```

Не показываем сокращения вроде `0/5 0$×2`: коэффициент уже применён к сумме.
